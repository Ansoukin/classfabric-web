# ClassFabric 官网视觉改版方案 v12

> 目标：让站点看起来像**「一款给教室用的、靠谱的 Windows 软件」**，而不是「一场硬件发布会」。
> 交付物：本方案 + 可点样张 `design/proposal.html`（访问 `/design/proposal.html`）。

---

## 一、诊断：现在的站不丑，但不"像一个牌子"

我把 `site.css`（1411 行）拆开统计了一遍，问题不是审美，是**没有约束**：

| 体检项 | 实测 | 后果 |
| --- | --- | --- |
| `border-radius` 取值 | **17 种**（2/3/4/5/6/8/9/10/12/14/16/18/20/24/28/50%/999…，其中 5px 用了 55 次） | 每个板块像不同人做的 |
| `box-shadow` | **47 处**，几乎每处都不一样 | 层次没有语言，"浮起来"失去含义 |
| 大标题字号 | **12 套 clamp**，上限从 36px 到 128px | 每个 section 都在喊，等于都没喊 |
| 渐变 | **38 个** + 9 处毛玻璃 | 首屏像 iOS 发布会落地页 |
| 壁纸 | 同一张 `wall.webp` 用在 **9 处** | 想靠壁纸拉开层次，结果全部糊平 |
| 设计反复 | CSS 里有「V11 视觉升级」「去玻璃化」「真机校准」三段互相覆盖 | 154 个选择器被重复定义，改一处要试三次 |
| 主色 | `--blue #62b3f2` 与渐变首档 `--g1 #8fdcff`、亮色主题 `#0a84ff` 三套蓝 | CTA 和标题抢色，品牌记不住 |

再叠加**语气错位**：产品是给班主任、电教管理员用的 Windows 工具，用户关心的是「能不能装在我学校那台一体机上 / 会不会崩 / 和原版差在哪」；而站点用 118px 渐变标题 + 滚动叙事，把这三件事分别推到了第 9、14、20 屏。

还有一个扎实的浪费：仓库里 **6 张真实截图 + 8 张灵动岛图**（`shot-*.webp`、`isl-*.webp`，共 370 KB）**一次都没被引用**；而页面中线却热链着上游的演示 mp4。

## 二、方案定位

**「课表语言」· Editorial Fluent**

三个支点，全部来自产品本身，不是流行趋势：

1. **母题 = 课表网格**。一张课程表本身就是"秩序"。用极淡的时间刻度网格线做背景肌理，取代渐变光晕——既有辨识度，又零成本、零加载。
2. **语气 = Fluent**。站点配色/圆角/字号与软件界面（深色 Fluent）同源，用户点开设置页不会有"换了家公司"的割裂感。
3. **排版 = 编辑式**。大标题收敛、小标题克制、正文可读；靠**留白与字号对比**建层级，而不是靠渐变和发光。

### 备选方向（同一次评审可以对比看）

| 方向 | 一句话 | 适合 | 主要代价 |
| --- | --- | --- | --- |
| **A（推荐）课表语言** | 秩序感 + Fluent + 实色 | 现在这个受众，长期可维护 | 需要重排首页信息顺序 |
| B 发布会电影感 | 保留现有 Apple 调性，只做收敛 | 想要"作品展示"感 | 老师仍然找不到"能不能装我的电脑" |
| C 文档站 | 完全走 docs：目录 + 截图 + 参数 | 极客受众 | 情感分低，转化依赖文案功力 |

## 三、设计系统（可直接落进 CSS 变量）

```css
:root{
  /* 色：1 主色 + 2 语义色，深色为默认 */
  --ink:#0A0D13; --surface:#12161F; --surface-2:#181D28;
  --fg:#F3F6FB; --muted:#A6B0C2; --faint:#6D7688;
  --line:rgba(255,255,255,.08); --line-strong:rgba(255,255,255,.16);
  --accent:#4C8DFF; --accent-hi:#6DA4FF; --on-accent:#05121F;
  --ok:#3DD9A4; --warn:#F0B44C;

  /* 字：6 档，全部封顶 */
  --fs-display:clamp(34px,4.4vw,58px);   /* 首屏 H1 */
  --fs-h2:clamp(26px,3vw,38px);          /* 板块标题 */
  --fs-h3:clamp(19px,1.6vw,22px);        /* 卡片标题 */
  --fs-lead:clamp(16px,1.3vw,18px);      /* 导语 */
  --fs-body:16px; --fs-sm:14px; --fs-micro:12.5px;

  /* 距离：8pt */
  --s1:4px; --s2:8px; --s3:12px; --s4:16px; --s5:24px; --s6:32px; --s7:48px; --s8:64px; --s9:96px;

  /* 圆角：4 档 */  --r-sm:8px; --r-md:12px; --r-lg:18px; --r-full:999px;

  /* 高度：2 档 + 首屏唯一一处品牌光晕 */
  --sh-1:inset 0 0 0 1px var(--line),0 1px 2px rgba(0,0,0,.35);
  --sh-2:0 24px 60px -28px rgba(0,0,0,.75),inset 0 0 0 1px var(--line-strong);
}
```

配套规则（写进代码注释，作为 review 依据）：

- **一个页面最多一个渐变**（Logo 字标）；渐变文字（`background-clip:text`）全站禁用。
- **毛玻璃只允许出现在吸顶导航**；其余用实色。
- **大标题每页 ≤ 2 个**；正文最深只到 `--muted`，不小于 `--faint`。
- **壁纸只出现在首屏**及其渐隐过渡；其余板块用墨底 + 网格。
- 中文字重：标题 700（现 800 显得糊），正文 400；中文负字距不超过 `-.02em`。

## 四、首页信息排序（这是方案里最重要的一页）

现状 8 个 section、平均滚动 6 屏才讲到"它是什么"。方案改成 6 屏、疑问即答案：

```
① 首屏        一句话价值 + 主 CTA + 4 条关键事实（系统/大小/架构/协议）+ 班牌样机
② 与上游的关系  ClassIsland / ClassFabric 两列对照：同步什么、沿用什么、增强什么、更新节奏
③ 提醒（灵魂）  灵动岛状态机演示 —— 进视口播一轮，右侧"重播"按钮，不再无限循环
④ 功能矩阵      6 张卡片：主界面 / 提醒 / 课表 / 调课 / 插件与主题 / 恢复模式
⑤ 真实截图      全宽画廊，启用闲置的 shot-*.webp 6 张，替代热链视频
⑥ 三步上手      + 下载 CTA（版本号实时读取，与下载页共用逻辑）
```

关键取舍：

- **首屏不放 logo 大图 + 渐变标语**，改为「价值句 + 事实条」。事实条是本次转化率提升的主要来源。
- **"和 ClassIsland 的关系"从第 9 屏提到第 2 屏**。这是全站最大的疑问，先答再讲情怀。
- **跑马灯（70s 无限滚动）删除**，其中 8 个灵动岛状态已经在 ③ 里被更好地说过一遍。
- 现有 19s 循环的 hero 演示（伪造鼠标轨迹点开窗口）**降级为静态样机 + 一个"看演示"按钮**：省 CPU、省焦虑，演示仍可看。

### 下载页

- 现在的版本信息来自 `/releases/latest`，会拿到只含 3 个附件、且缺 x86/arm64 的旧版（详见审计报告）。
- 改为「最近一个含附件的 release」，并按架构分组成三行：`x64 / x86 / arm64`，每行给「安装包 / 便携」两种，标文件大小与发布日期，附 SHA256 折叠区。
- 顶部一条 `预发布` 提示条（当命中 prerelease 时），避免用户以为拿到的是稳定版。

### 关于页

- 保留现有内容（写得已经不错），只做版式：目录改左侧粘性窄栏（现已是），正文宽 68ch，FAQ 用 `details` 已合适。
- 新增一张「改了什么」时间线（从 GitHub 提交/release 自动生成摘要，静态写死 8–10 条即可）。

## 五、动效与可访问性

- 全套动效收敛为 3 类：**进场淡入位移（120–300ms）**、**灵动岛状态切换（240ms）**、**悬停描边变化（160ms）**。全部 `prefers-reduced-motion` 下关闭（现有代码已尊重，保持）。
- 滚动叙事（`position:sticky` 3000px 钉住）只留给 ③ 提醒一节；其余板块正常滚动。
- 对比度：正文 `#A6B0C2` on `#0A0D13` ≈ 9.1:1，✅ AA/AAA；亮色主题把 accent 换成 `#0B66D0`（现为 `#0a84ff`，白底上偏亮）。
- 补三项：skip link（跳至主内容）、`<noscript>` 静态版本链接、`aria-selected` 配 `role="tab"`。
- 移动端：首屏样机在 ≤560px 收成「时间 + 灵动岛 + 4 个课时块」，隐藏科目圆点，避免 320px 溢出。

## 六、实施计划（建议分批上，每批可独立回滚）

| 批次 | 内容 | 改哪里 | 工作量 | 风险 |
| --- | --- | --- | --- | --- |
| **P0 令牌层** | 新增 `--*` token 与 4 条硬规则；按钮/卡片/导航换新值 | `site.css` 顶部 + 组件段 | 0.5 天 | 低：不动 HTML |
| **P1 首屏** | 新 hero（文案 + 事实条 + 班牌样机）+ 关系屏前移 | `build.py: home()` | 1 天 | 中：结构改动，需 diff 审查 |
| **P2 收口** | 删跑马灯、hero 循环改"播一次"、启用 6 张截图做画廊、删死代码 | `build.py` + `site.js` | 1 天 | 中：删动效需确认 |
| **P3 下载页** | 架构分组 + 预发布提示 + 校验值 | `build.py: download()` + `site.js` | 0.5 天 | 低 |
| **P4 精修** | 亮色主题、可访问性三项、移动端断点、SEO 小修 | `site.css` + `build.py` | 1 天 | 低 |

**约 4 个工作日**；如果只想先看效果，做 **P0 + P1** 即可（1.5 天），其余保持原样也不会打架。

为什么风险可控：`build.py` 是字符串拼装、产物可复现（我已验证 `python3 tools/build.py` 零 diff），所以每批改完都能 `git diff` 逐行看产物，不引入构建工具、不加依赖。

### 验收标准

1. `python3 tools/build.py` 后 diff 只包含预期改动；
2. 1440 / 768 / 390 三档无横向滚动、首屏 CTA 在 768 以上不折行；
3. Lighthouse 移动端 Performance ≥ 90、Accessibility ≥ 95（删掉跑马灯与视频热链后性能会明显回升）；
4. 全站 `border-radius` 取值 ≤ 5 种、`box-shadow` ≤ 6 种、渐变 ≤ 3 处（可用 `grep` 复核，我会在提交说明里附统计）。
